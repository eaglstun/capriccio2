## Why this exists

CAPRICCIO was generated by Fable from a handful of prompts. This is another
one: reskin it as vaporwave. The point is a **new look, not a new game**.

## Decisions I made that you should check

1. **"struedel" → Strudel** (strudel.cc), the TidalCycles port to JS. If you
   meant something else, stop here.
   - Install `@strudel/core` + `@strudel/webaudio`, **not** `@strudel/web` —
     that one is a 1.5MB opinionated bundle, more than twice the size of the
     entire game.
   - Do **not** install the unscoped `strudel` package. Different project
     entirely (a front-end framework).
   - Even the lean path is ~630KB unpacked pre-tree-shake against a 662KB
     game. **This is the single biggest size risk in the job** and the brief
     tells Fable to measure it and report back rather than assume.
2. **Sound effects stay hand-rolled.** `AUDIO.md` documents the existing
   convention — pink-noise wind, physically-modelled bells, birds, chisels,
   all synthesized, zero sample files. Strudel is for _music_ only.
3. **No new asset types at all.** No bitmaps, no video, no audio files, no
   webfonts. Everything procedural or already present.

## The prompt

You are modifying **CAPRICCIO**, a Piranesi-styled browser city-builder, into
a **vaporwave** version. This is a **reskin**. The game must play exactly the
same.

### Repository layout

- `src/` — 18 ES modules, the game's source. **Edit here.**
- `public/` — the original production build. **Reference only, never edit.**
- `dist/` — build output from `yarn build`.
- Read `RENDERING.md`, `AUDIO.md`, `SIMULATION.md`, `src/README.md` first.
  They are accurate and were verified against the running game.

Package manager is **yarn**, not npm.

### Absolute constraints

**Do not change gameplay.** Specifically, do not touch:

- `06-infill.js` — the `pickPocket` scoring function and its weights
- the five stat formulas in `17-bootstrap.js` (`updateQualityMeters`)
- the pocket model, `applyAction`, or anything in `05-world.js` that changes
  what gets built
- the save format in `08-save.js` — it is an event-sourced action log and
  **existing saves must still load**
- the building catalogue's `key` values in `09-catalogue.js` (labels and hint
  text may change; keys are load-bearing)
- population, resources, or request logic

**Do not add binary assets.** No images, no video, no audio files, no
webfonts, no CDN fetches at runtime. Everything must be procedural or a
system font. The whole appeal of this game is that it fits on a floppy disk —
do not be the reason it stops fitting.

**Do not rename identifiers.** `src/` is generated from the original bundle by
`tools/split_bundle.py` with a rename map. Hand-renaming will be overwritten
and will break the integrity check.

### Where the look actually lives

The renderer is already structured so a reskin is mostly re-parameterising it.
Two passes in two frames of reference (see `RENDERING.md`):

| what                                                  | where                                        |
| ----------------------------------------------------- | -------------------------------------------- |
| ink colour `uInkCol` `#241d12`, hatch frequency       | `00-shaders.js`, uniforms block              |
| paper colour `#efe8d8` — the clear colour AND the sky | `00-shaders.js`                              |
| stone palette (`#e8e0cb`, `#e2d9c0`, …)               | `01-materials.js`, the palette factory       |
| sky, ink outlines, paper grain, vignette              | `00-shaders.js`, the post pass               |
| HUD typography and chrome                             | `16-hud.js`, the stylesheet template literal |
| fonts: Iowan Old Style / Palatino Linotype            | `16-hud.js`                                  |

**The existing post pass maps onto vaporwave almost one-to-one.** Use that
rather than inventing new machinery:

- **The sky already draws faint horizontal bands, denser toward the horizon.**
  Recolour that and it _is_ the vaporwave sun. This is the single highest-
  value change in the job.
- **Paper grain** — two frequencies of static screen-space "tooth" — becomes
  CRT scanlines and VHS chroma noise. Same code shape, different numbers.
- **Vignette** stays, deepened.
- **Ink outlines** (depth edge + normal edge) become neon rim light. The
  distance fade and near-boost logic should stay as-is.
- **Triplanar world-space hatching** should stay. It is what makes the strokes
  sit on the stone instead of crawling across the screen, and it will read as
  a dot/scanline dither just as well as it reads as engraving. Recolour;
  do not replace.

### Aesthetic direction

Sunset gradient sky — magenta into orange into deep purple. Cyan and hot-pink
neon for edges. Chrome and pastel for stone. Grid horizon if it falls out of
the existing terrain contour lines cheaply; do not force it. Wide letter-
spacing in the HUD. Keep the layout exactly where it is — the HUD's
composition is good and is not what needs changing.

Restraint matters more than saturation. The original's confidence comes from a
tight palette and a lot of empty paper. Keep that discipline; change the hues.

### One addition: an interstitial between title and game

After the player clicks BEGIN / CONTINUE, and **before** the game view
appears, show these two lines, then fade to the game:

```text
faint horizontal burin lines, denser toward horizon, broken by cloudy noise
dusk warms and darkens the paper sky a touch near the sun's side
```

Reproduce that text **exactly**. Do not rewrite, extend, or "improve" it.

These are real comments from the sky shader in `00-shaders.js` — notes the
program wrote to itself about how to draw its own sky. They survived
minification only because comments inside template literals are not stripped.
Nobody was meant to read them. Putting them on screen is the whole idea, so
the wording is not yours to edit.

Implementation notes:

- This is the one place you may touch the boot sequence in `17-bootstrap.js`.
  Keep the change minimal: the veil-dismiss handler already exists — add a
  step, do not restructure the flow.
- It must be **skippable** — a click or any key goes straight through. Never
  trap a returning player behind it. Two or three seconds unattended.
- Style it as an epigraph: centred, quiet, wide letter-spacing, low contrast
  against the sunset. It should read as something overheard, not as a splash
  screen. No box, no border, no button.
- Text only. No new assets, no webfonts.
- It must not delay or block world construction — the game should already be
  built behind it, exactly as it is behind the title screen today.

The `//` comment markers are dropped above, on the judgement that it reads
better as an epigraph than as source. If keeping them would look better in
context — code-as-aesthetic is very much on-theme — that call is yours.

### Audio

**Music — new, via Strudel.** Add `@strudel/core` and `@strudel/webaudio`
(not `@strudel/web`). Write a slow vaporwave pattern: lush pads, slow chords,
heavy detune, something in the 60–80 BPM range.

- **Synthesized sources only.** No `samples()` calls, nothing that fetches
  from a CDN.
- Bind it to game state the way the existing audio is — see below.
- **Measure and report the bundle size delta.** If Strudel pushes the bundle
  past roughly 1MB, stop and say so rather than shipping it.

**Sound effects — keep the existing system**, described in `AUDIO.md`. It is
already fully procedural: pink-noise wind on a 0.07Hz gust LFO, water gain
falling off squared with distance, a bell whose higher partials decay faster,
birds only in daylight, chisels only while building. Retune these for the new
mood if you like — different filter frequencies, more chorus, more decay — but
**do not replace synthesis with samples** and do not remove the binding
between sound and simulation state. That binding is the best thing about the
audio: the ambience is a readout of the game.
