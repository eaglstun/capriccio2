# CAPRICCIO — project notes

## What this is

A browser city-builder in the style of Piranesi: you raise arches, stairs and
vaults, and citizens come live among them. **Not written by the repo owner.**
It was generated by Fable (a Claude model) at Ethan Mollick's direction, one of
a series of city builders in the style of famous artists. He posted it publicly
in July 2026 and deployed it at `capriccio-city.netlify.app`.

This directory holds a **downloaded production build**. There is no source.

## Layout

```text
public/
  index.html                     975 bytes, loads the bundle as type="module"
  assets/index-DCXbw2vV.js       the entire game
```

That is the whole project. No `package.json`, no `src/`, no build config, no
git repo.

## Critical facts about the bundle

- **No source map ships with it.** Work here is archaeology, not
  decompilation. Never claim to have recovered original names — they were
  destroyed at build time.
- **Identifiers are 100% mangled.** Every declaration in the app section is
  ≤2 chars. Do not try to read it top-down like source.
- **String literals survived** and are the primary research anchor. Minifiers
  cannot alter string contents or string object-keys.
- **Roughly the first 25,000 lines are three.js** (with GLSL shader source
  inlined) and the last ~6,000 are the actual game. This seam is _estimated_;
  it has not been precisely measured yet.
- The bundle uses **Web Audio synthesis** (`bandpass`, `aTone`, `birdTimer`)
  rather than audio files.
- Save data lives in `localStorage` under **`capriccio-save-v1`**.

## The file on disk has been reformatted

The bundle as deployed is **662,267 bytes / 4,364 lines**. The local copy was
pretty-printed by an editor on 2026-07-27 and is now **925,795 bytes / 30,968
lines**. It still parses clean (`node --check` passes) and behaves identically
— formatting does not change semantics — but **the local file is no longer
byte-identical to what is deployed.** Use 662KB when citing the real artifact's
size publicly; use the local line numbers only for navigation.

## Running it

The bundle requests `/assets/...` by absolute path, so it must be served from
`public/` as the web root. Static server, no build step:

```sh
cd public && python3 -m http.server 8123 --bind 127.0.0.1
```

Then open `http://127.0.0.1:8123`. Verify with:

```sh
curl -s -o /dev/null -w "%{http_code} %{content_type}\n" \
  http://127.0.0.1:8123/assets/index-DCXbw2vV.js
```

The `type="module"` script tag means **the bundle will be refused by the
browser if served with the wrong MIME type** — it must come back as
`text/javascript`. Python's `http.server` gets this right.

## `src/` is a reading copy, not a build

`src/` holds the app section cut into 18 files by `tools/split_bundle.py`. It
is a **lossless partition** — nothing renamed, nothing reordered, verified by
byte-identical reassembly.

**It is not runnable and not importable.** There are no `import`/`export`
statements; every file references identifiers declared in the others, because
the original was one concatenated scope with mangled names. Do not attempt to
build or serve from `src/` until scope analysis has been done.

`public/` remains the only runnable copy. If you change how the split works,
re-run `python3 tools/split_bundle.py --write` — it aborts rather than emit a
partition it cannot verify. See `src/README.md`.

## Working method

Preferred order, by payoff:

1. **Runtime introspection beats static reading.** Breakpoint in devtools and
   inspect live objects — mangled names don't matter when you can see an
   object's real shape.
2. **Serialized state beats both.** The save blob is the data model written
   out with its keys intact.
3. **Anchor static reads on surviving strings,** then read outward from those
   call sites. Never start at line 1.

See `PLAN.md` for the phased investigation and current progress.

## Don't

- Don't edit the bundle. It's a build artifact and the only copy of this game
  on disk; there is no source to regenerate it from. Analyze, extract, and
  write findings to separate files.
- Don't re-derive the deployed size from the local file — see above.
